# Архитектурный обзор Qt Chat Client (v2)

## 1. Введение

Этот документ предоставляет комплексный обзор архитектуры второй версии десктопного чат-клиента, разработанного на C++ с использованием фреймворка Qt.

Приложение представляет собой современный клиент для обмена мгновенными сообщениями, который взаимодействует с сервером по протоколу TCP. Ключевой особенностью данной версии является модульная, компонент-ориентированная архитектура, построенная на принципах разделения ответственности и активном использовании паттерна **Модель-Представление-Делегат (Model-View-Delegate)**. Такой подход обеспечивает высокую масштабируемость, сопровождаемость и тестируемость кода.

## 2. Ключевые архитектурные принципы

### 2.1. Компонентно-ориентированный UI

Вместо монолитного подхода, где один класс (`MainWindow`) управляет всем пользовательским интерфейсом, v2 разбивает UI на логические, независимые и переиспользуемые компоненты:

-   `LoginWidget`: Отвечает исключительно за экраны входа и регистрации.
-   `ChatViewWidget`: Инкапсулирует всю область просмотра чата, включая заголовок, историю сообщений и поле ввода.
-   `SearchResultsPopup`: Специализированный виджет для отображения результатов поиска пользователей.

### 2.2. Паттерн Модель-Представление-Делегат (MVD)

Для отображения списка сообщений используется мощный паттерн Qt — MVD. Это позволяет полностью отделить данные от их визуального представления.

-   **Модель (`ChatMessageModel`):** Хранит список сообщений (`QList<ChatMessage>`) и является единственным "источником правды". Она ничего не знает о том, как сообщения будут выглядеть.
-   **Представление (`QListView`):** Стандартный виджет Qt, который отвечает за отображение данных, предоставляемых моделью.
-   **Делегат (`ChatMessageDelegate`):** Кастомный "художник", который отрисовывает каждый отдельный элемент в представлении. Именно он отвечает за создание "пузырей" сообщений, их выравнивание, цвет и отображение дополнительной информации (например, времени).

### 2.3. Централизованный координатор

Класс `MainWindow` больше не управляет деталями UI напрямую. Вместо этого он выполняет роль **координатора** или **контроллера**. Его основные задачи:
-   Инициализация и компоновка всех UI-компонентов.
-   Управление всей сетевой логикой и взаимодействием с сервером.
-   Связывание компонентов между собой через механизм сигналов и слотов, обеспечивая их слабую связанность.

## 3. Описание компонентов

### `MainWindow`
-   **Файлы:** `mainwindow.h`, `mainwindow.cpp`, `mainwindow.ui`
-   **Роль:** Центральный класс приложения, дирижер оркестра.
-   **Ответственность:**
    -   Управляет `QStackedWidget`, который переключает отображение между `LoginWidget` и основным интерфейсом чата.
    -   Инициализирует `QTcpSocket` и управляет соединением с сервером.
    -   Содержит `m_responseHandlers` — диспетчер для обработки ответов от сервера.
    -   Владеет `ChatMessageModel` и кешем пользователей (`m_userCache`).
    -   Принимает сигналы от UI-компонентов (например, `loginRequested`, `sendMessageRequested`) и преобразует их в сетевые запросы.
    -   Получает данные от сети и обновляет соответствующие модели или состояние приложения.

### `LoginWidget`
-   **Файлы:** `loginwidget.h`, `loginwidget.cpp`, `loginwidget.ui`
-   **Роль:** Самодостаточный виджет для аутентификации пользователя.
-   **Ответственность:**
    -   Предоставляет пользователю интерфейс для ввода логина/пароля и данных для регистрации.
    -   Не выполняет никакой сетевой логики.
    -   При нажатии кнопок генерирует сигналы `loginRequested(...)` и `registerRequested(...)`, передавая введенные данные.
    -   Предоставляет публичные слоты для управления своим состоянием извне (например, `onRegistrationSuccess`, `clearFields`).

### `ChatViewWidget`
-   **Файлы:** `chatviewwidget.h`, `chatviewwidget.cpp`, `chatviewwidget.ui`
-   **Роль:** Виджет, инкапсулирующий всё, что связано с отображением одного чата.
-   **Ответственность:**
    -   Содержит заголовок с именем и статусом собеседника, `QListView` для сообщений и панель ввода.
    -   Предоставляет публичный API для управления своим состоянием (например, слот `updateHeader(...)`).
    -   Генерирует сигналы о действиях пользователя: `sendMessageRequested(...)`, `replyToMessageRequested(...)`, `editMessageRequested(...)` и т.д.
    -   Владеет элементами UI, но не данными, которые в них отображаются (модель для `QListView` устанавливается извне).

### `ChatMessageModel`
-   **Файлы:** `chatmessagemodel.h`, `chatmessagemodel.cpp`
-   **Роль:** Модель данных для сообщений.
-   **Ответственность:**
    -   Наследуется от `QAbstractListModel`.
    -   Хранит `QList<ChatMessage>` — полный список сообщений текущего чата.
    -   Предоставляет слоты для атомарных операций с данными: `addMessage`, `editMessage`, `removeMessage`, `clearMessages` и т.д.
    -   При изменении данных уведомляет все подключенные представления с помощью сигналов `beginInsertRows`, `dataChanged` и т.д., что приводит к автоматическому обновлению UI.

### `ChatMessageDelegate`
-   **Файлы:** `chatmessagedelegate.h`, `chatmessagedelegate.cpp`
-   **Роль:** Кастомный отрисовщик для элементов `QListView`.
-   **Ответственность:**
    -   Наследуется от `QStyledItemDelegate`.
    -   Переопределяет метод `paint()` для отрисовки каждого сообщения. Внутри этого метода с помощью `QPainter` рисуются цветные "пузыри", текст сообщения, время и другие элементы. Логика выравнивания (справа для исходящих, слева для входящих) реализована здесь.
    -   Переопределяет метод `sizeHint()` для динамического вычисления высоты каждого сообщения в зависимости от длины текста, что обеспечивает корректное отображение многострочных сообщений.

### `ChatFilterProxyModel`
-   **Файлы:** `chatfilterproxymodel.h`, `chatfilterproxymodel.cpp`
-   **Роль:** Прокси-модель для фильтрации сообщений.
-   **Ответственность:**
    -   Наследуется от `QSortFilterProxyModel`.
    -   Размещается между `ChatMessageModel` и `QListView`.
    -   Переопределяет метод `filterAcceptsRow()`, который возвращает `true` только для тех сообщений, чей `payload` содержит искомую строку.
    -   Обеспечивает элегантную и производительную реализацию поиска по истории чата.

## 4. Потоки данных (Data Flow)

### Сценарий 1: Отправка сообщения
1.  Пользователь вводит текст в `QLineEdit` внутри `ChatViewWidget` и нажимает "Отправить".
2.  `ChatViewWidget` генерирует сигнал `sendMessageRequested(text)`.
3.  Слот `MainWindow::onSendMessageRequested(text)` получает этот сигнал.
4.  `MainWindow` создает объект `ChatMessage` со статусом `Sending` и временным ID (`tempId`).
5.  `MainWindow` вызывает `m_chatModel->addMessage(msg)`. Модель добавляет сообщение в свой список и уведомляет `QListView`, который тут же его отрисовывает (с помощью делегата).
6.  `MainWindow` формирует и отправляет на сервер JSON-запрос `private_message`.
7.  Сервер обрабатывает сообщение и присылает обратно подтверждение (`echo`) с постоянным ID.
8.  `MainWindow` в обработчике `handlePrivateMessage` находит сообщение по `tempId` и вызывает `m_chatModel->confirmMessage(...)`, обновляя его ID и статус на `Sent`. Модель снова уведомляет представление, и статус сообщения в UI обновляется.

### Сценарий 2: Получение сообщения
1.  `MainWindow` через `onReadyRead` получает от сервера JSON-объект типа `private_message`.
2.  Диспетчер вызывает `handlePrivateMessage`.
3.  Обработчик парсит JSON в объект `ChatMessage`.
4.  Если сообщение пришло от пользователя, с которым открыт чат (`fromUser == m_currentChatPartner.username`), `MainWindow` вызывает `m_chatModel->addMessage(incomingMsg)`.
5.  Модель добавляет сообщение и уведомляет `QListView`.
6.  `QListView` запрашивает у модели данные для нового элемента, и `ChatMessageDelegate` отрисовывает новое входящее сообщение. UI обновляется автоматически.

## 5. Сетевое взаимодействие и стилизация

-   **Протокол:** Взаимодействие с сервером происходит по TCP. Каждое JSON-сообщение предваряется `quint32` значением, указывающим его размер, для корректного разделения сообщений в потоке.
-   **Стилизация:** Весь внешний вид приложения определяется в глобальном файле `styles.css`, который загружается при старте. Это позволяет легко менять тему оформления и поддерживать единообразный стиль во всем приложении, используя стандартные селекторы QSS.

## 6. Заключение

Архитектура второй версии чат-клиента является robust (надежной), поддерживаемой и масштабируемой. Четкое разделение ответственности между компонентами, инкапсуляция логики и применение паттерна Модель-Представление-Делегат не только упрощают текущую разработку и отладку, но и закладывают прочный фундамент для добавления нового функционала в будущем с минимальными затратами.
