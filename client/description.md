# Описание архитектуры и структуры проекта: Чат-клиент (Версия 3)

## 1. Обзор проекта

Этот документ описывает внутреннюю структуру и архитектуру десктопного чат-клиента, разработанного с использованием C++ и фреймворка Qt 6. Приложение представляет собой клиент для клиент-серверной системы обмена сообщениями.

**Ключевые технологии и парадигмы:**
-   **Язык:** C++17
-   **Фреймворк:** Qt 6
-   **Сетевое взаимодействие:** TCP/IP сокеты (`QTcpSocket`)
-   **Протокол обмена данными:** Кастомный протокол поверх TCP, использующий JSON для сериализации сообщений.
-   **Архитектурные паттерны:**
    -   **Model-View-Delegate (MVD):** Для эффективного отображения списков (сообщения, контакты).
    -   **Сигналы и слоты:** Для организации асинхронного и слабосвязанного взаимодействия между компонентами.
    -   **Централизованное управление состоянием:** `MainWindow` выступает в роли "дирижера", управляя всеми основными компонентами и состоянием приложения.

**Основной функционал (на Версию 3):**
-   Регистрация и авторизация пользователей.
-   Список контактов с отображением онлайн-статуса.
-   Обмен личными сообщениями в режиме реального времени.
-   Статусы сообщений (отправка, отправлено, доставлено, прочитано).
-   Редактирование и удаление собственных сообщений.
-   Индикатор набора текста ("печатает...").
-   Динамическая подгрузка истории сообщений при прокрутке.
-   **Ответы на сообщения (цитирование).**
-   Глобальный поиск пользователей.
-   Кастомизируемый UI через таблицы стилей QSS.

## 2. Структура файлов проекта

Проект организован по стандартному для Qt принципу, разделяя заголовочные файлы, файлы реализации, UI-формы и ресурсы.

-   **Заголовочные файлы (`.h`)**:
    -   `mainwindow.h`: Главное окно приложения.
    -   `loginwidget.h`: Виджет экрана входа и регистрации.
    -   `chatviewwidget.h`: Виджет отображения одного чата.
    -   `chatmessagemodel.h`: Модель данных для сообщений в чате.
    -   `chatmessagedelegate.h`: Делегат для кастомной отрисовки сообщений.
    -   `chatfilterproxymodel.h`: Прокси-модель для фильтрации сообщений.
    -   `searchresultspopup.h`: Всплывающий виджет для результатов поиска.
    -   `structures.h`: Определения ключевых структур данных (`User`, `ChatMessage`).

-   **Файлы реализации (`.cpp`)**:
    -   Соответствующие `.cpp` файлы для каждого заголовочного файла, содержащие реализацию логики.
    -   `main.cpp`: Точка входа в приложение.

-   **Формы (`.ui`)**:
    -   `mainwindow.ui`: Базовая разметка главного окна.
    -   `loginwidget.ui`: Разметка виджета входа/регистрации.
    -   `chatviewwidget.ui`: Разметка виджета чата, включая новый виджет для ответов.

-   **Ресурсы и стили**:
    -   `resources.qrc`: Файл ресурсов Qt, который компилирует иконки и стили в исполняемый файл.
    -   `styles.css`: Глобальная таблица стилей QSS, определяющая внешний вид всего приложения.
    -   `/icons/`: Папка с иконками, используемыми в интерфейсе.

## 3. Архитектура и компоненты

### 3.1. `MainWindow` — Центральный контроллер

`MainWindow` является ядром приложения. Он не содержит сложной UI-логики, но координирует работу всех остальных компонентов.

-   **Обязанности:**
    -   **Управление соединением:** Инициализирует `QTcpSocket`, подключается к серверу и обрабатывает события `connected`, `disconnected` и `readyRead`.
    -   **Обработка протокола:** В слоте `onReadyRead` читает данные из сокета, парсит JSON и, основываясь на поле `"type"`, вызывает соответствующий обработчик из `QMap<QString, ResponseHandler> m_responseHandlers`. Этот механизм делает добавление новых команд от сервера очень простым.
    -   **Управление состоянием:** Хранит глобальное состояние, такое как `m_currentUsername`, `m_currentChatPartner`, кэш пользователей `m_userCache`, а также состояние UI (например, `m_editingMessageId`, `m_replyToMessageId`).
    -   **Сборка интерфейса:** Динамически создает и компонует основной интерфейс в методе `buildMainUI`, вместо того чтобы жестко задавать его в `.ui` файле.
    -   **Взаимодействие компонентов:** Связывает сигналы от UI-виджетов (например, `sendMessageRequested` от `ChatViewWidget`) со слотами, которые формируют JSON-запросы и отправляют их на сервер через `sendJson()`.

### 3.2. `LoginWidget` — Экран входа

Простой виджет, отвечающий исключительно за аутентификацию.

-   **Структура:** Содержит `QStackedWidget` с двумя страницами: для входа и для регистрации.
-   **Логика:** Собирает данные из `QLineEdit` и по нажатию кнопок эмитирует сигналы `loginRequested` или `registerRequested`. Он ничего не знает о сети и полностью отделен от `MainWindow`.
-   **UX Улучшение (v3):** Имеет кнопку для показа/скрытия пароля.

### 3.3. `ChatViewWidget` — Интерфейс чата

Виджет, представляющий собой окно диалога с одним пользователем.

-   **Структура:** Состоит из трех частей:
    1.  `headerWidget`: Заголовок с именем собеседника и его статусом.
    2.  `chatHistoryView (QListView)`: Список сообщений.
    3.  `messageInputWidget`: Панель ввода сообщения, которая теперь включает `replyWidget`.
-   **`replyWidget` (Новое в v3):** Специальный виджет, который появляется над полем ввода, когда пользователь отвечает на сообщение. Он показывает, кому и на какой текст идет ответ. Управляется методами `showReplyUI()` и `hideReplyUI()`.
-   **Обязанности:** Отображает данные, предоставленные `MainWindow`, и сообщает ему о действиях пользователя через сигналы (`sendMessageRequested`, `editMessageRequested`, `replyCancelled` и т.д.).

### 3.4. Паттерн Model-View-Delegate для сообщений

Для отображения чата используется мощная связка MVD, которая обеспечивает высокую производительность и гибкость.

-   **`ChatMessageModel` (Модель):**
    -   Наследуется от `QAbstractListModel`.
    -   Хранит сообщения *текущего* открытого чата в `QList<ChatMessage>`.
    -   **Ключевая оптимизация (v3):** Для быстрого поиска сообщений по ID (необходимого для функции ответов) была добавлена `QMap<qint64, ChatMessage> m_messageMap`. Это позволяет находить сообщения за O(log n) вместо O(n).
    -   Предоставляет API для добавления, изменения и удаления сообщений (`addMessage`, `editMessage` и т.д.), уведомляя при этом View об изменениях.

-   **`QListView` (Представление):**
    -   Стандартный Qt-виджет, используемый в `ChatViewWidget`. Он запрашивает у модели данные и передает их делегату для отрисовки.

-   **`ChatMessageDelegate` (Делегат):**
    -   Наследуется от `QStyledItemDelegate`.
    -   **Главная обязанность:** Полностью переопределяет отрисовку каждого элемента списка (`paint()`) и расчет его высоты (`sizeHint()`).
    -   **Логика отрисовки (v3):**
        1.  Получает `ChatMessage` из модели.
        2.  Проверяет, является ли сообщение ответом (`replyToId > 0`).
        3.  Если да, запрашивает у модели через `getMessageById()` исходное сообщение и рисует блок цитаты.
        4.  Рисует основной "пузырь" сообщения, выравнивая его по правому (исходящие) или левому (входящие) краю.
        5.  Внутри пузыря рисует текст сообщения и строку с метаданными (время, статус, пометка "изм.").
        6.  `sizeHint()` рассчитывает итоговую высоту, суммируя высоту блока цитаты (если есть) и высоту основного пузыря.

### 3.5. `structures.h` — Фундамент данных

Этот файл определяет две основные структуры, используемые во всем приложении.

-   **`struct User`:** Представляет пользователя. Содержит поля `id`, `username`, `displayName`, `lastSeen`, `isOnline` и др.
-   **`struct ChatMessage`:** Представляет одно сообщение. Содержит все необходимые поля: `id`, `payload` (текст), `timestamp`, `fromUser`, `toUser`, `isOutgoing`, а также `replyToId` для связи с цитируемым сообщением. Включает `enum MessageStatus` для отслеживания состояния сообщения.

## 4. Схема взаимодействия при ответе на сообщение (Ключевой сценарий V3)

1.  **Пользователь** вызывает контекстное меню на сообщении в `ChatViewWidget` и выбирает "Ответить".
2.  `ChatViewWidget` эмитирует сигнал `replyToMessageRequested(messageId)`.
3.  **`MainWindow`** ловит этот сигнал в слоте `onReplyToMessage`.
4.  `MainWindow` вызывает `m_chatModel->getMessageById(messageId, ...)` для получения данных цитируемого сообщения.
5.  `MainWindow` вызывает `m_chatViewWidget->showReplyUI(...)`, передавая имя автора и текст для отображения в панели ответа.
6.  `MainWindow` сохраняет ID в `m_replyToMessageId`.
7.  **Пользователь** пишет текст ответа и нажимает "Отправить".
8.  `ChatViewWidget` эмитирует `sendMessageRequested(newText)`.
9.  Слот `onSendMessageRequested` в `MainWindow` видит, что `m_replyToMessageId` не равен нулю.
10. Он создает новый `ChatMessage`, присваивая ему `replyToId = m_replyToMessageId`.
11. Сообщение добавляется в модель для мгновенного отображения и отправляется на сервер в виде JSON, где также присутствует поле `reply_to_id`.
12. `MainWindow` сбрасывает `m_replyToMessageId = 0` и вызывает `m_chatViewWidget->hideReplyUI()`.
